Project 1 — Completed
F1 Podium Prediction

Binary Classification Pipeline  ·  Completed May 2026  ·  View on GitHub →

A supervised machine learning pipeline predicting Formula 1 podium finishes (top 3 classification) using qualifying position and constructor standings as primary predictors. The project established a reproducible ETL pipeline ingesting 6,432 race results across 15 seasons from the Jolpica API, and benchmarked Logistic Regression against Random Forest classifiers. This project serves as the portfolio foundation — demonstrating a clean binary classification pipeline, proper train/test split, and documented GitHub workflow — before moving to more complex multi-class and deep learning problems.

Problem & Approach

Predicting whether a driver will finish on the podium (positions 1–3) from qualifying data and season-to-date constructor performance. Framed as binary classification: podium (1) vs no podium (0).

The project focused on establishing a clean, reproducible data pipeline — from API ingestion through feature engineering to model evaluation — as the primary learning objective, rather than maximising prediction accuracy.

Data & Features

Source: Jolpica API (formerly Ergast) — historical F1 results (2008–2023, 15 seasons, 6,432 race entries).

Features used: Grid position (qualifying result), constructor points at time of race, driver points at time of race, circuit — processed via an automated ETL pipeline.

Models & Results

Logistic Regression and Random Forest classifiers benchmarked on a held-out test set. Evaluation via accuracy, precision, recall, and F1 score. Class imbalance handled via class_weight='balanced'.

Key finding: grid position is the dominant predictor — reflecting the real-world difficulty of overtaking in F1. Constructor standing adds modest lift particularly for midfield predictions.

Progression to Project 2

Project 1 establishes binary classification fundamentals. Project 2 (Premier League) extends this to three-class prediction, richer feature engineering across 5 categories, temporal data handling, and a five-model benchmark — a significant step up in complexity.

Project 2 — Full Proposal
Predicting Match Outcomes in the English Premier League

A Multi-Class Classification Approach Using Contextual and Temporal Features  ·  Target: Jan 2027

This project develops a machine learning pipeline to predict the outcome of English Premier League (EPL) football matches — win, draw, or loss from the home team's perspective — using a multi-class classification framework. Building on prior work in binary sports outcome prediction (Project 1: F1 Podium Prediction), this project significantly extends the complexity of the problem domain by introducing contextual, temporal, and relational features absent from simpler prediction tasks. The central hypothesis is that match outcome prediction can be meaningfully improved beyond baseline by incorporating form-based momentum signals, head-to-head history, squad-level performance metrics, and match condition variables. The project will benchmark multiple classification algorithms including Logistic Regression, Random Forest, XGBoost/LightGBM, and a simple neural network baseline, evaluated using macro-averaged F1 score as the primary metric given class imbalance across outcomes.

1. Background & Motivation

Football match outcome prediction is a well-studied problem in sports analytics and machine learning, with applications ranging from betting market modelling to tactical decision support. The English Premier League presents a particularly challenging prediction environment due to its competitive balance — unlike many European leagues, the EPL has no dominant team that wins predictably each season, meaning naive baseline models perform poorly.

The draw class introduces the defining challenge of this problem. In binary classification (win/not-win), draws are absorbed into the negative class. In a three-way formulation, draws must be predicted explicitly — a class that human experts and statistical models alike consistently underperform on. Dixon and Coles (1997) demonstrated that modelling the correlation structure between goals scored introduces material prediction lift over independent Poisson models, while Rue and Salvesen (2000) showed that Bayesian dynamic strength parameters — capturing team form — further improve calibration. More recently, gradient boosted tree ensembles have been shown to outperform traditional statistical models when rich feature sets are available (Hubáček et al., 2019).

This project applies modern supervised learning methods to this problem, with an emphasis on feature engineering as the primary source of competitive advantage over baseline approaches.

2. Research Questions

RQ1Which feature categories — form metrics, head-to-head history, squad statistics, or match conditions — contribute most to predictive accuracy?
RQ2Does incorporating rolling time-window form (e.g. last 5 matches) outperform season-aggregate statistics?
RQ3Which classification algorithm provides the best calibrated probability estimates for the three-class outcome distribution?
RQ4Can draw prediction be materially improved beyond a random baseline through targeted feature engineering?

5. Methodology

A time-series train/test split will be used — training on seasons 2015/16 to 2022/23, validating on 2023/24, and testing on 2024/25. This preserves temporal integrity and prevents data leakage, which is a common failure mode in sports prediction literature.

Hyperparameter optimisation via Optuna (Bayesian optimisation) with 5-fold time-series cross-validation. Class imbalance handled via class weights, SMOTE, and threshold adjustment — all evaluated independently.

7. Limitations

Injury and suspension data are not publicly available in structured form — a significant confound not captured in this model
Managerial changes mid-season are not modelled, despite their material impact on team performance
In-match events (red cards, early goals) are excluded — this is a pre-match prediction model only
Transfer window effects — squad quality changes between seasons are partially captured by xG metrics but not squad value directly

Project 3 — Full Proposal
Mastering Atari with Deep Q-Networks

Replicating and Extending Human-Level Reinforcement Learning  ·  Target: Apr 2027

This project implements and extends a Deep Q-Network (DQN) agent to play Atari 2600 games using raw pixel observations, replicating the landmark result of Mnih et al. (2015) and extending it with three algorithmic improvements: Double DQN (van Hasselt et al., 2016), Dueling Network Architecture (Wang et al., 2016), and Prioritized Experience Replay (Schaul et al., 2016). The primary environment is Breakout-v4 (OpenAI Gymnasium), with secondary evaluation on a second Atari game to test cross-environment generalisation. The project is motivated by its direct intellectual lineage to DeepMind's AlphaGo and AlphaZero — the same core ideas of learning value functions from raw observations, refined over successive generations. The central hypothesis is that each algorithmic extension produces measurable improvement in sample efficiency and final game score over the vanilla DQN baseline, and that their combination (Rainbow-lite) outperforms any single extension alone.

1. Background & Motivation

Reinforcement learning (RL) is the branch of machine learning concerned with how an agent learns to act in an environment to maximise cumulative reward. Unlike supervised learning — where labels are provided — an RL agent must discover through trial and error which actions lead to good outcomes. The field is foundational to some of the most significant AI achievements of the past decade.

The breakthrough moment came in 2013 when DeepMind published Playing Atari with Deep Reinforcement Learning (Mnih et al., 2013), demonstrating that a single neural network could learn to play 49 Atari games directly from raw pixel inputs — without any game-specific feature engineering. The agent surpassed human-level performance on 29 of them. The formalized Nature paper (Mnih et al., 2015) introduced the canonical DQN architecture combining a convolutional neural network with two key stabilisation techniques: experience replay and target networks.

The intellectual lineage from DQN to AlphaGo (Silver et al., 2016) is direct. AlphaGo uses policy and value networks learned through a combination of supervised learning from human games and reinforcement learning through self-play — the same principle of learning value estimates from experience, scaled to a much harder problem. Implementing DQN is therefore not just a portfolio exercise: it is engaging with the foundational idea that produced the most important AI breakthrough of the 2010s.

This project extends vanilla DQN with three improvements that together form the basis of the Rainbow agent (Hessel et al., 2018), one of the most sample-efficient general-purpose RL algorithms:

  • Double DQN — decouples action selection from action evaluation to reduce overestimation bias in Q-values
  • Dueling Networks — separates the value function V(s) and advantage function A(s,a) to learn which states are valuable independently of actions
  • Prioritized Experience Replay — samples transitions with high temporal-difference error more frequently, improving sample efficiency

2. Research Questions

RQ1Can a vanilla DQN implementation trained from scratch match the published benchmark scores of Mnih et al. (2015) on Breakout-v4?
RQ2Does each algorithmic extension (Double DQN, Dueling Networks, Prioritized Replay) individually improve sample efficiency and final score over the vanilla baseline?
RQ3Does combining all three extensions (Rainbow-lite) outperform any single extension alone?
RQ4Does the trained agent generalise to a second Atari environment without retraining the architecture?

3. Environment & Problem Specification

Primary environment: Breakout-v4 (OpenAI Gymnasium / ALE). The agent observes raw pixel frames (84×84 grayscale after preprocessing), stacked in groups of 4 consecutive frames to capture motion. Actions: 4 discrete (NOOP, FIRE, RIGHT, LEFT). Reward: +1 per brick destroyed. Episode terminates on loss of all lives.

Secondary environment: Pong-v4 — two-player paddle game, used to evaluate cross-environment robustness of the trained architecture without modification.

Preprocessing pipeline: Grayscale conversion → resize to 84×84 → frame stacking (last 4 frames) → reward clipping to [-1, 1] → no-op at episode start (random 1–30 steps) — matching standard Atari preprocessing from the original paper.

4. Architecture & Implementation

Vanilla DQN network: Three convolutional layers (32×8×8, 64×4×4, 64×3×3) followed by two fully connected layers (512 units, then output). ReLU activations throughout. Trained with Adam optimiser, learning rate 1e-4.

Key DQN mechanisms:

Experience Replay Buffer (1M transitions) Target Network (updated every 10k steps) ε-greedy exploration (ε: 1.0 → 0.1 over 1M steps) Batch size: 32 Discount factor γ = 0.99

Extensions architecture: Double DQN modifies the Bellman target computation only. Dueling Networks add a branching layer splitting into V(s) and A(s,a) streams before recombining. Prioritized Replay replaces the uniform sampling strategy in the replay buffer with TD-error-weighted sampling.

5. Experimental Design

Five agents trained independently, each from scratch with identical seeds for reproducibility:

AgentExtensionsPurpose
Vanilla DQNNoneBaseline — replicate Mnih et al. (2015)
Double DQNDouble Q-targetsTest overestimation reduction
Dueling DQNDueling architectureTest state-value decomposition
PER DQNPrioritized replayTest sample efficiency improvement
Rainbow-liteAll three combinedTest combined effect

Each agent trained for 10M environment steps. Evaluation: mean episode reward over 30 evaluation episodes every 250k training steps, with no-op starts and ε=0.05 during evaluation. Training curves plotted for all agents to visualise sample efficiency.

6. Evaluation Metrics

Primary: Mean episode score at 10M steps (compared against published DQN baseline of ~400 for Breakout).

Secondary: Sample efficiency — steps to reach 50% of final performance. Learning stability — variance of evaluation scores across training. Cross-environment transfer — Pong score without retraining.

7. Connection to DeepMind & AlphaGo

AlphaGo's policy and value networks were initialised via supervised learning from human games, then refined through RL self-play using policy gradient methods. The core idea — approximating a value function with a neural network, trained on experience — is exactly what DQN does. AlphaZero (Silver et al., 2017) removed even the human data, relying entirely on self-play RL. The progression from DQN (pixels → Q-values) to AlphaGo (board state → policy + value) to AlphaZero (no human priors at all) is the central arc of deep RL research in the 2010s. This project engages with the origin of that arc.

8. Limitations

Compute constraints — full DQN training on Atari requires significant GPU time. Training will be limited to 10M steps (vs 50M in original paper) using Google Colab Pro or university compute if available
Single-environment depth — testing on only two Atari games limits generalisability claims. Full Rainbow was evaluated on 57 games
Hyperparameter sensitivity — RL algorithms are notoriously sensitive to hyperparameters; results may differ from published benchmarks due to subtle implementation differences
No distributional RL — the Rainbow-lite omits distributional Q-learning (C51), one of Rainbow's most impactful components, due to implementation complexity

Project 4 — Full Proposal
Fine-tuning Transformers for FCA Regulatory Document Intelligence

Multi-label Classification and Obligation Extraction from UK Financial Regulation  ·  Target: Jun 2027

This project fine-tunes pre-trained transformer models on a curated corpus of FCA (Financial Conduct Authority) regulatory documents to perform two NLP tasks: (1) multi-label classification of document sections by regulatory domain (Consumer Duty, Suitability, Vulnerable Clients, RMAR, Data Protection), and (2) regulatory obligation extraction — identifying sentences that impose specific compliance requirements on firms versus contextual or explanatory text. Four transformer models are benchmarked: BERT-base, RoBERTa-base, FinBERT (pre-trained on financial text), and LegalBERT (pre-trained on legal text), with a GPT-based zero-shot baseline for comparison. The project contributes a novel annotated FCA regulatory corpus — the first publicly available dataset of this kind — and produces a fine-tuned model that feeds directly into Amaea's compliance intelligence layer, replacing the current embedding-only retrieval system with a classification-aware pipeline. The central hypothesis is that domain-specific pre-training (FinBERT or LegalBERT) will outperform general-purpose BERT on both tasks, and that obligation extraction can be solved as a sentence-level sequence classification problem with high precision on the OBLIGATION class.

1. Background & Motivation

The transformer architecture (Vaswani et al., 2017) and its derivatives — BERT (Devlin et al., 2019), RoBERTa (Liu et al., 2019) — have become the dominant paradigm for NLP tasks. The key insight of BERT is masked language model pre-training: by training on vast text corpora to predict masked tokens, the model learns deep contextual representations that transfer effectively to downstream tasks with minimal fine-tuning data.

In regulated industries, NLP has significant potential to automate document analysis that currently requires expensive human expertise. The FCA publishes thousands of pages of regulatory guidance, policy statements, thematic reviews, and enforcement notices each year. IFA compliance teams must stay current with all of it. A model that can automatically classify regulatory content and extract obligations from new publications would provide material commercial value — replacing hours of manual reading with automated alerts.

This project addresses a specific gap in the existing literature: while legal NLP has been applied to EU law (Chalkidis et al., 2020 — LexGLUE), US case law, and GDPR documentation, there is no published work on FCA regulatory text. The annotated corpus produced by this project is itself a contribution to the field.

Connection to Amaea: The trained model feeds directly into the Amaea compliance intelligence layer, replacing the current embedding-search approach with a classification-aware pipeline. When new FCA guidance is published, the model automatically tags it by regulatory domain and flags obligation sentences for immediate compliance review — a core product feature.

2. Research Questions

RQ1Does domain-specific pre-training (FinBERT, LegalBERT) outperform general-purpose BERT and RoBERTa on multi-label FCA document classification?
RQ2Can regulatory obligation extraction be solved as sentence-level sequence classification with precision > 0.85 on the OBLIGATION class?
RQ3How does GPT-based zero-shot classification compare to fine-tuned BERT variants on both tasks — and at what annotation cost does fine-tuning break even?
RQ4Does a model trained on FCA Consumer Duty documents generalise to obligations extracted from FCA enforcement notices (out-of-distribution test)?

3. Dataset & Annotation

Source corpus: The FCA regulatory document collection assembled for the Amaea compliance intelligence layer — including PS22/9 (Consumer Duty final rules), FG22/5 (Consumer Duty guidance), FG23/2 (board report guidance), FG21/1 (vulnerable customers), and additional FCA publications ingested via the sitemap scraper. Total corpus: 100+ documents, ~500k tokens.

Task 1 annotation — multi-label classification: Each document chunk (paragraph level, ~150 tokens) is labelled with one or more of seven regulatory domains:

Consumer Duty Suitability & Annual Reviews Vulnerable Clients RMAR & Reporting Data Protection / UK GDPR Enforcement & Sanctions General Conduct

Task 2 annotation — obligation extraction: Each sentence is labelled as one of four classes: OBLIGATION (firms must / firms are required to), GUIDANCE (firms should / we expect), CONTEXT, or EXAMPLE. Annotation target: 2,000 sentences across 20 documents (approx. 8 hours manual annotation). Inter-annotator agreement measured on 200-sentence overlap using Cohen's Kappa.

4. Models & Experimental Design

Fine-tuning approach: each model fine-tuned independently on the annotated FCA corpus with 80/10/10 train/validation/test split, stratified by regulatory domain. Hyperparameter search via Optuna (learning rate, batch size, warmup steps). All experiments run 3× with different random seeds; results reported as mean ± standard deviation.

5. Evaluation Metrics

Task 1 (multi-label classification): Micro-F1 (primary — accounts for label imbalance), Macro-F1 (secondary — treats all domains equally), Hamming Loss (proportion of incorrectly predicted labels), per-label precision and recall.

Task 2 (obligation extraction): Precision, recall, and F1 on the OBLIGATION class specifically (high precision is the priority — a false obligation is worse than a missed one in a compliance context). Overall accuracy and weighted F1 reported for completeness.

6. Integration with Amaea

The production pipeline built from this project: new FCA document published → ingested into corpus → chunked → classified by domain (Task 1 model) → obligations extracted (Task 2 model) → high-confidence obligations pushed to the Amaea compliance alert system with source citation.

This replaces the current embedding-only retrieval with a two-stage system: classification first (to filter to relevant domain), retrieval second (to find the specific passage). Expected improvement: fewer irrelevant results in compliance queries, higher precision on obligation-specific questions.

The annotated FCA corpus is also a proprietary data asset for Amaea — the first structured, labelled dataset of FCA regulatory obligations, which competitors cannot replicate without the same annotation effort.

7. Limitations

Small annotated dataset — 2,000 annotated sentences is modest for fine-tuning; results may not generalise beyond FCA Consumer Duty documents without additional annotation
Single annotator bias — annotation by a single annotator introduces subjectivity; inter-annotator agreement measured on a 200-sentence subset but full dataset is not double-annotated due to time constraints
Class imbalance — OBLIGATION sentences are a minority class; requires careful handling via class weights or focal loss to avoid the model defaulting to CONTEXT predictions
Context window limitations — BERT-based models process 512 tokens maximum; long FCA documents must be chunked, potentially splitting obligations across chunks and losing cross-sentence context

9. Connection to Imperial NLP Module

This project directly engages with core topics from Imperial's NLP optional module: pre-trained language models, transfer learning and fine-tuning, sequence classification, named entity recognition, and evaluation of NLP systems. The domain-specific pre-training comparison (FinBERT vs LegalBERT vs BERT) addresses a live research question in NLP — when does domain adaptation matter, and how much? — making this more than a standard fine-tuning exercise.
